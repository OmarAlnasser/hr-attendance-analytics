# نظام تحليل الحضور والأداء للموارد البشرية

HR Attendance & Performance Analytics System

> **النسخة الحية والتوثيق بالإنجليزية:** [README.md](README.md). النشر على Render وSupabase موضح في [docs/deployment.md](docs/deployment.md).

نظام محلي قابل للتشغيل يحوّل بصمات أجهزة الحضور وتقييمات الأداء الشهرية إلى بيانات موثوقة ومؤشرات قابلة للتحقق. يتكون من:

- تطبيق ويب بـ Flask، بصلاحيات مطبّقة على الخادم.
- معالجة بـ Pandas وقاعدة SQLite، مع طبقة وصول للبيانات قابلة للنقل.
- تقرير PDF شهري.
- نموذج تنبؤ تجريبي للمراجعة البشرية فقط.
- مواد جاهزة لبناء تقرير Power BI.
- **جديد في v2:** لوحة حية لحضور اليوم، وطلبات إجازة وتصحيح بصمة منسية مع صندوق موافقات، وإدارة الحسابات من الواجهة، واستيراد الموظفين من CSV.
- **جديد في v3:** الواجهة وتقرير PDF بالعربية والإنجليزية، ودور «المدير العام» فوق الموارد البشرية، وبطاقة المستخدم باسمه ودوره، وعبارات واضحة بدل الرموز الداخلية. التفاصيل في `CHANGELOG.md`.

> **كل البيانات المرفقة اصطناعية** (بذرة ثابتة 42). الأرقام توضّح طريقة عمل النظام، ولا تُعد دليلًا على أداء أي مؤسسة حقيقية أو على تحسّن فعلي.

الواجهة وتقرير PDF متاحان بالعربية والإنجليزية، والتبديل بينهما من أسفل الشريط الجانبي أو من صفحة الدخول. مرئيات Power BI بالإنجليزية مع أعمدة أسماء عربية إضافية. التفاصيل في `docs/assumptions.md`.

## التشغيل السريع

المتطلبات: Python 3.11 أو أحدث. الاختبار تم على 3.12.3.

```bash
cd hr-attendance-analytics
python -m venv .venv
# Windows: .venv\Scripts\activate      Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env            # Windows: copy .env.example .env
python -c "import secrets; print(secrets.token_hex(32))"
# الصق الناتج في .env بعد HR_SECRET_KEY=

python -m hr_analytics demo     # قرابة 30 ثانية
python -m hr_analytics.web      # ثم افتح http://127.0.0.1:5000
```

أمر `demo` يعيد إنشاء قاعدة البيانات، ثم ينفّذ بالترتيب:

1. توليد 12 شهرًا من البيانات الاصطناعية: 121 موظفًا في 7 أقسام، منها الإدارة التنفيذية للمدير العام.
2. تحميل البيانات الأساسية والتقييمات.
3. استيراد 12 ملف بصمات، منها ملف Excel.
4. معالجة الحضور اليومي.
5. تدريب النموذج التجريبي وتقييمه.
6. تصدير ملفات Power BI.
7. إنتاج تقريرَي PDF لآخر شهر: بالعربية وبالإنجليزية.

كلمة المرور المشتركة للحسابات التجريبية تُكتب في `instance/demo_credentials.txt`، وهو ملف خارج Git. يمكن بدلًا من ذلك تحديدها بـ `HR_DEMO_PASSWORD` في `.env`.

| الحساب | الدور | ما يراه |
|---|---|---|
| `e0000` | المدير العام (عبدالعزيز المطلق) | كل ما تراه الموارد البشرية، ويقرّر في طلبات موظفيها وتقييمهم وفي منح صلاحيتها |
| `e0101` | الموارد البشرية (عمر الناصر) | كل المؤسسة، والاستيراد، والإعدادات، وسجل التدقيق |
| `e0001` | مدير قسم Operations | قسمه فقط + سجله |
| `e0071` | مدير قسم IT | قسمه فقط + سجله |
| `e0002` | موظف | بياناته فقط |

## سير العمل الكامل لمستخدم جديد

1. **توليد البيانات:** `python -m hr_analytics demo`، أو الخطوات منفصلة (انظر جدول الأوامر).
2. **تشغيل التطبيق:** `python -m hr_analytics.web` ثم الدخول بحساب `e0101`.
3. **استيراد حضور:**
   - افتح Import punches، وارفع ملف CSV أو Excel، واختر المنطقة الزمنية.
   - تظهر نتيجة التحقق: صفوف جديدة، ومكررات تم تخطيها، وصفوف معزولة مع سبب كل صف.
   - تُعاد معالجة الأيام المتأثرة تلقائيًا.
   - رفع الملف نفسه مرة ثانية يُرفض دون تكرار أي بصمة.
4. **إدخال تقييم:**
   - افتح Evaluations، واختر الشهر، ثم Evaluate أمام موظف.
   - أدخل 4 درجات من 1 إلى 5 مع تعليق.
   - الدرجة الموزونة تُحسب بالأوزان السارية، وكل تعديل يُحفظ في سجل التغييرات.
5. **التحقق من المؤشرات:**
   - لوحة Overview تعرض كل معدل مع بسطه ومقامه.
   - ملف الموظف يعرض شريط الشهر يومًا بيوم.
   - صفحة Attendance تصدّر نفس الصفوف إلى CSV أو Excel.
6. **إنتاج التقرير:**
   - من Monthly reports، أو بالأمر `python -m hr_analytics run-monthly --period 2026-08 --all-departments`.
   - التشغيل الثاني للفترة نفسها يُتخطى تلقائيًا.
7. **Power BI:** اتبع `powerbi/README.md`.

### ميزات v2 في سير العمل

| الصفحة | من يراها | ما تفعله |
|---|---|---|
| **Today** | HR والمدير | من حضر، ومن تأخر، ومن لم يحضر بعد، ومن سيأتي لاحقًا، ومن في إجازة. تتحدث كل دقيقة. حقلا التاريخ والوقت يعيدان عرض أي لحظة سابقة، مثل 27 أغسطس الساعة 09:30. لا تكتب شيئًا في القاعدة |
| **My requests** | كل من له سجل موظف | طلب إجازة، والإبلاغ عن بصمة دخول أو خروج منسية. يمكن سحب الطلب المعلّق وإلغاء إجازة معتمدة لم تبدأ |
| **Approvals** | HR والمدير | الطلبات المعلّقة لمن يديرهم، مع عدّاد في الشريط الجانبي. يظهر بجانب كل تصحيح حال اليوم الحالي وبصماته المسجلة. الرفض يتطلب ملاحظة، ولا أحد يعتمد طلبه بنفسه |
| **User accounts** | HR | إنشاء حساب بكلمة مؤقتة تظهر مرة واحدة، وإعادة تعيين كلمة المرور، والتعطيل، ومنح صلاحية HR، وتعطيل حسابات المنتهية خدمتهم بضغطة واحدة |
| **Import employees** | HR | ملف CSV (يوجد قالب للتنزيل). الفحص يسبق الحفظ، ثم يُحفظ الكل أو لا شيء، مع إنشاء حسابات عند الطلب |
| البحث السريع | HR والمدير | حقل في أعلى الشريط الجانبي يبحث بالاسم أو الرمز أو البطاقة |

جرّبها بعد `demo`:

1. ادخل بـ `e0001` (مدير Operations)، وافتح Approvals، واعتمد الإجازة المطلوبة.
2. ادخل بـ `e0101` (HR)، واعتمد أحد تصحيحات البصمة، ثم افتح ملف الموظف: اليوم تحوّل من «بصمة واحدة» إلى «حاضر».
3. افتح Today، ثم اضغط رابط «Replay» في التنبيه الأصفر.

**لوحة حية فعلًا:** البصمات تصل عبر ملفات الأجهزة. اجدول `python -m hr_analytics import-punches <مجلد التصدير>` كل 5 دقائق (cron أو Task Scheduler، انظر `scripts/`). الملف المستورد مسبقًا يُتخطى تلقائيًا، والبصمة المكررة لا تُخزَّن مرتين.

### ميزات v3

| الميزة | ما تفعله |
|---|---|
| **العربية والإنجليزية** | رابط «العربية / English» أسفل الشريط الجانبي وفي صفحة الدخول. كل الصفحات والرسائل والتصديرات تتبع اللغة المختارة، والصفحة تنقلب من اليمين إلى اليسار |
| **تقرير PDF بالعربية** | حقل «اللغة» في صفحة التقارير، أو `--lang ar` في الأوامر |
| **المدير العام** | دور أعلى من الموارد البشرية: يعتمد طلبات موظفي الموارد البشرية ويقيّمهم، ويمنح صلاحيتها ويسحبها. طلباته الشخصية تُسجَّل معتمدة فورًا |
| **بطاقة المستخدم** | أسفل الشريط الجانبي: الأحرف الأولى من الاسم بلون الدور، والاسم، والمسمى، والقسم |
| **عبارات واضحة** | «لا توجد بصمة خروج» بدل `missing_out_punch`، و«6 بطاقات غير معروفة» بدل `UNKNOWN_BADGE: 6`، في الصفحات وفي التقرير |

**الترقية من v1 أو v2:** لا خطوات يدوية. عند تشغيل التطبيق أو `init-db`، تُرقّى قاعدة البيانات القائمة إلى المخطط v3 في مكانها مع الحفاظ على البيانات. ويُنصح بنسخة احتياطية قبلها.

## الأوامر

تُشغَّل كلها بالصيغة `python -m hr_analytics <command>`، ويعرض `--help` خيارات كل أمر.

| الأمر | الوظيفة |
|---|---|
| `init-db [--reset]` | إنشاء قاعدة البيانات، أو حذفها وإعادة إنشائها |
| `generate-data [--seed --employees --months --start]` | توليد البيانات الاصطناعية في `data/synthetic` |
| `seed` | تحميل البيانات الأساسية والحسابات والتقييمات من البيانات المولّدة |
| `import-punches PATH... [--tz --device]` | استيراد ملفات أو مجلدات، ثم معالجة الأيام المتأثرة |
| `process --start --end [--as-of]` | إعادة حساب الحضور اليومي لفترة معينة |
| `train-model` | تدريب النموذج التجريبي وتقييمه، أو التحول للقواعد إن كانت البيانات غير كافية |
| `report --period YYYY-MM [--department CODE] [--force] [--lang en\|ar\|both]` | تقرير PDF واحد، بالإنجليزية افتراضيًا |
| `run-monthly [--period] [--all-departments] [--lang]` | للجدولة؛ الافتراضي هو الشهر السابق وباللغتين |
| `export-powerbi` | كتابة ملفات النموذج النجمي في `output/powerbi` |
| `create-user --username --role gm\|hr\|manager\|employee [--employee-code]` | إنشاء حساب حقيقي بكلمة مرور تُدخل بشكل مخفي |
| `demo` | المسار الكامل على بيانات اصطناعية، مع طلبات معلّقة للعرض |

```bash
python -m unittest discover -s tests -t .
```

## بنية المشروع

```
hr_analytics/
  config.py            الإعدادات من متغيرات البيئة (HR_*)؛ لا أسرار في الكود
  db/                  schema.sql، الاتصال، repos.py (طبقة الوصول للبيانات)
  domain/              قواعد الحضور، والتقييم والأوزان، وتعريفات المؤشرات (دوال نقية)
  pipeline/            الاستيراد والتحقق والعزل، ومعالجة الحضور اليومي
  security/scope.py    قواعد الصلاحيات المشتركة بين الويب والتقارير والأوامر
  services/            حفظ التقييمات مع السجل، وقواعد المراجعة، وتحميل البيانات،
                       وقواعد طلبات الإجازة وتصحيح البصمة (requests.py، v2)
  synthetic/           مولّد البيانات الاصطناعية
  ml/                  النموذج التجريبي وتقييمه
  reports/             تقرير PDF (عربي وإنجليزي، arabic.py للتشكيل والاتجاه) ومشغّل يمنع التكرار
  i18n.py, i18n_ar.py  اختيار اللغة والجمل العربية
  labels.py            تحويل الرموز المخزنة إلى عبارات بشرية باللغتين
  exports/             تصدير النموذج النجمي لـ Power BI
  web/                 تطبيق Flask (views، templates، static)
powerbi/               M وDAX وRLS ومواصفات الصفحات ودليل البناء
samples/               عينات جاهزة: تقريرا PDF، وتقرير النموذج، وملفات Power BI
docs/screenshots/      لقطات من التطبيق
docs/                  الافتراضات، وتعريفات المؤشرات، والنموذج، والتحقق، والانتقال للإنتاج
scripts/               أمثلة جدولة (cron وTask Scheduler)
tests/                 اختبارات unittest
```

## ما هو خارج النطاق

- **ملف `.pbix`:** لم يُنشأ لعدم توفر Power BI Desktop في بيئة البناء. البديل المرفق يكفي لبنائه.
- **إرسال البريد:** غير مطلوب ولا يوجد، والتقارير تُحفظ على الخادم فقط.
- **التعرف على الوجه (OpenCV/DeepFace):** مؤجل كامتداد اختياري. السبب مذكور في `docs/production_migration.md`.
